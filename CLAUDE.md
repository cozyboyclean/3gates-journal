# Notes for Claude

- Owner: Aron (cozyboyclean). Windows desktop app built with Electron; web version is a claude.ai artifact.
- Shared UI code lives in `app/core.js`, `app/views.js`, `app/forms.js`. Desktop-only behavior is gated on `DESK` (the `window.desktop` preload bridge); web-only on `window.claude`. Keep both working.
- `app/index.html` is the desktop page (offline fonts and Chart.js bundled, CSP). `web/journal.html` is the artifact page; keep their CSS in sync when changing styles.
- Trades have a book: no `kind` = executed, `kind: 'bt'` = backtest, `kind: 'missed'` (+ `missReason`). `allTrades()`/`scoped()` default to executed only; pass `{ book }` for others. Only the Backtest & missed and Executed vs backtest screens use the other books.
- Playbook (app/playbook.js): `trade.pb = { state, htf, locs: [name], level, trigs: [id], thesis, evidence, objective, g1, g2, g3, pre }` (older trades may have a single `trig` / `loc`; always read via `pbTrigIds` / `pbLocs`). Library in `settings.playbook` (items have stable ids; status approved/candidate/deprecated; `pairs` = 'htfId|trigId'; deleted items keep a `{code,name}` snapshot in `deleted`, read via `pbRef`). A trade is compliant only if every tagged trigger is approved and pair-approved with the setup.
- The old `trade.setup` ("Model") is retired: hidden from the form, filters, Edge Finder and Settings; shown read-only as "Legacy model". Don't reintroduce or auto-map it. Compliance is computed by `pbClassify` from rules only, never P&L. Never auto-fill pb on existing trades or approve candidates without Aron saying so.
- Layered entries: optional `trade.entries = [{price, size, time}]` (only stored when 2+ fills). `trade.entry`/`size`/`entryTime` always hold the size-weighted average, total and first fill (see `syncEntries` in forms.js), so all stats keep using them.
- Media items in `trade.shots`: `{file|id|data, kind?: 'video', name?, note?}`.
- Never change the stored data shape in a breaking way: users' `journal.json` must keep loading. Add fields with defaults (see `mergeDefaults`).
- To ship: bump `version` in package.json, replace `release-notes.md` with plain-language notes for Aron, commit, push to main. No tag needed (tag pushes are refused from Claude sessions). `.github/workflows/release.yml` runs on package.json changes, skips versions already released, builds on windows-latest and publishes a non-draft release `vX.Y.Z` that electron-updater reads. Check the run with the GitHub Actions UI or ask Aron if it's not visible.
- Local Linux builds need wine + wine32 (`npm run dist`); CI does not.
- Psychology module (app/psych.js, spec in docs/PSYCH_MODULE.md): day data in `S.journal[date].psy`, trade data in `trade.psy`, settings in `settings.psy` (merged by `mergePsy`). `psyEval(date)` is the single engine (cached per render via PSY_CACHE). Validity comes from `pbClassify`; never add P&L to the process score except the hard risk checks. Each invalid trade is charged to exactly one category. Tests: `tests/psych-test.js` (hypothetical sessions, headless Chrome) must pass.
